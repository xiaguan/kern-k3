# FlashKDA, vLLM dev

Source: https://github.com/vllm-project/FlashKDA/tree/b59532f1f464fbd536272780e30df5bf6a2ccc02

Pinned September 11, 2026 revision. MIT license copied alongside the source.
CUTLASS submodule: `5c149f52a436782210263fb2f19b354443a61c6a`.

`csrc/fwd.h`, `smxx/utils.cuh`, `smxx/fwd_kernel1.cuh`, and
`smxx/fwd_kernel2.cuh` are verbatim upstream. `smxx/fwd_launch.cu` only trims
explicit instantiations to D=128, FP32 input/output state, no checkpoint,
fixed-length input and int64 sequence offsets. Both V=128 and V-split=64
recurrence kernels are compiled. Kernel mathematics are unchanged.

Build with CUDA 13.0 for SM103a:

```sh
CUTLASS_INCLUDE=/path/to/pinned-cutlass/include \
  bash source/flash-kda-vllm/build.sh build/flash_kda_vllm_d128.cubin
```

The manifest ABI is generated by `scripts/gen_flash_kda_vllm.py`. It reads
entry symbols from the cubin with `readelf`, retains the original operation
interface, and replaces workspace TMA descriptors with raw bulk-copy pointers.
Shared storage sizes from upstream types are 21504 bytes (K1), 98432 (K2),
and 68608 (K2 V-split). K1 uses 128 threads, K2 uses 192. Checkpoint pointers
are null because this manifest has no checkpoint requests.

Old FlashKDA sources and cubins remain available for reference manifests.

A clean rebuild was checked against the bundled artifact: all executable and
constant sections match. CUDA-generated symbol tables differ between builds,
so a fresh cubin need not have the same whole-file SHA-256. The bundled artifact
is the exact binary used for the recorded bench and test runs.
